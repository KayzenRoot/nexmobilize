# Data model — PROPOSED
Todos os registros operacionais com tenant_id e IDs opacos; FKs compostas tenant_id+id; RLS com teste de bypass; timestamps UTC; migrações versionadas. Dados pessoais minimizados.
Tenant, User, Membership(role,status), Worker(external_ref,display_name,status), Contractor, Site, Contract, WorkerAssignment(worker,contract,site,role).
PolicyVersion(source_ref,effective_from,to,approved_by,hash), Requirement(policy_version,type,applies_to,rule,required), MobilizationCase(assignment,policy_version,status,sla_due), CaseRequirement(requirement,document_version,status).
Document(kind,owner_ref), DocumentVersion(object_key,sha256,mime,size,scan_status), Extraction(version,field,value,source_locator,confidence,provider_version), Review(case,reviewer,decision,reason), Dossier(case,manifest_hash,version,review_id), Submission(case,dossier,channel,external_ref,submitted_at,evidence), ExternalDecision(submission,status,evidence,observed_at), Task, Notification, AuditEvent, OutboxJob, OutcomeLedger(case,definition,measured_at,evidence,unique_key).
Case states: DRAFT, COLLECTING, IN_REVIEW, CHANGES_REQUIRED, READY, SUBMITTED, EXTERNAL_APPROVED, EXTERNAL_REJECTED, EXPIRED, CANCELLED. Transições explícitas; READY só após revisão e validação; APPROVED externo exige evidência. Sem estado de aptidão médica. Revogação/expiração invalida prontidão e notifica, sem alterar retrospectivamente evidências.
