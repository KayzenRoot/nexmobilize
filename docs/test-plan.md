# Test & Benchmark Plan
Unit: regras de vigência e aplicabilidade, estados/transições, idempotência, datas limite, dedup, métricas. Integration: migrations PostgreSQL, RLS multi-tenant, sessão/RBAC, storage/quarentena, worker retries e DLQ, outbox, manifest hash, restore. E2E: contrato -> trabalhador -> caso -> docs sintéticos -> review -> dossier -> submissão -> decisão externa; rejeição, expiração, reabertura e revogação. Negative: cross-tenant IDs, privilege escalation, MIME falso, arquivo malicioso, prompt injection, OCR ambíguo, ausência de evidência, dupla cobrança, replay, retenção e logs.
Gold dataset sintético versionado (>=100 casos/1000 docs proposto); medir precisão/recall por campo, abstenção, falso READY (zero no conjunto crítico), taxa de revisão, custo e latência. Nada de alegações de acurácia antes de benchmark; IA não dispensa revisão. Baseline com recursos e versões registrados; p95 NFR04, throughput, fila e custos; load sem dados reais.
CI: doc links, lint/typecheck/build/unit/integration/E2E, dependency/secret/SAST scan, SBOM e pinning quando aplicável; branch checks. Evidence: base/head, comandos, contagens, logs redigidos, cobertura de regras críticas, riscos e delta. Repetir restore e smoke em ambiente de piloto.
