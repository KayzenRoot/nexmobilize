# Architecture — PROPOSED
Modular monolith first: TypeScript web/API (Next.js candidato), PostgreSQL, armazenamento de objetos privado S3-compatible, worker assíncrono e fila transacional PostgreSQL, OCR local candidato (Tesseract), adaptador LLM desativado por padrão. Docker Compose local, CI GitHub Actions sujeito a quota/termos. Versões e licenças pinadas após qualificação, nenhuma dependência comercial assumida. Avaliar Supabase ou VPS existente apenas mediante ADR, limites, LGPD e autorização; sem criação de conta/deploy agora.
Bounded contexts: Identity/Tenancy; Workforce; Contract/Policy; Document Intake; Evidence/Extraction; Rules/Review; Case/Delivery; Notifications; Audit/Reporting. UI nunca consulta bucket ou banco privilegiado diretamente; serviços aplicam autorização e RLS como defesa adicional. Worker com identidade limitada, tenant explícito, outbox e leases.
Flow: upload -> quarantine -> scan -> classify -> extract -> validate -> review -> dossier -> authorized submission -> external evidence -> closure. Fail closed. IA apenas sugestão estruturada; regras versionadas e revisão humana decidem prontidão. Nenhuma decisão de aptidão. 
Interfaces: DocumentStore, Scanner, Extractor, RuleEvaluator, NotificationTransport, SubmissionAdapter (manual MVP), AuditSink. ZEUS opcional futuro, sem acoplamento. Evitar microsserviços prematuros.
ADR técnico obrigatório para dependências, auth, storage, crypto, providers e deployment.
