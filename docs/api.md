# API contracts — PROPOSED
REST /api/v1; JSON schema/OpenAPI gerado no incremento; auth servidor, tenant derivado de sessão, nunca confiar em tenant fornecido. Erros problem+json com code, correlationId, sem PII; 401/403/404/409/422/429 conforme contrato; paginação cursor; idempotency key para writes repetíveis, optimistic locking.
Endpoints: /workers, /contracts, /sites, /assignments; /policies/{id}/versions, /requirements; /cases, /cases/{id}/requirements, /cases/{id}/reviews, /cases/{id}/dossiers; /documents/upload-intents, /documents/{id}/complete, /documents/{id}/download; /cases/{id}/submissions, /submissions/{id}/decisions; /tasks, /notifications, /reports/outcomes, /audit-events.
Upload-intent vinculado a tenant/caso e expira; complete verifica hash/tipo e põe em quarentena. Review exige versão, reason e revisão válida. Submission registra ação autorizada, não chama portais no MVP. Decisão externa exige evidence_ref e operador habilitado. APIs de exportação/eliminação de dados com autorização reforçada, auditoria e revisão de retenção. Contratos de providers sem PII real por padrão.
