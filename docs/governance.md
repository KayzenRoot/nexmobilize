# Engineering governance
ANALYZE -> SOURCE CHECK -> NEXT NECESSARY -> WORK ORDER -> CONTEXT LOCK -> PREFLIGHT -> EXECUTOR -> TESTS/EVIDENCE -> PR -> AUDIT -> APPROVED/CORRECTION REQUIRED/BLOCKED -> CHECKPOINT DELTA -> SQUASH MERGE -> NEXT.
WO fields: OBJECTIVE, CONTEXT, SCOPE, OUT OF SCOPE, FILES/SOURCES, REQUIREMENTS, ARCHITECTURE RULES, CONSTRAINTS, AC, TESTS, DELIVERABLES, REVIEW FORMAT pt-BR, STOP CONDITION. Stable ID branch/PR/evidence; lock base SHA and critical docs hashes, mark STALE if drift. Evidence includes SHAs, diffs, test counts, CI, security, migrations, risks, checkpoint proposal. HIGH_ASSURANCE for auth, sensitive docs, external evidence, deployment.
Proposed ruleset: protect main, PR required, squash only, no force-push/deletion, require docs-validation then runtime checks, no bypass; verify actual GitHub settings and availability; if connector cannot configure, delegate to executor, keep gate BLOCKED. CI least privilege, pin actions SHAs once qualified; no paid services. Public repo must contain synthetic fixtures only. PR review in pt-BR. No canonical promotion by executor alone.
